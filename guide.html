How it works

Every tool on this site runs inside your browser tab. Here is what that actually means.

The short version

You pick a file. The browser reads it into memory with the File API. JavaScript — running on your own machine — edits the PDF and hands the result back as a download. There is no backend that could receive your file, so there is nothing to upload to.

What does the work

pdf-lib
Reads, edits and writes PDF structure — merging, splitting, rotating, cropping, drawing text and images, forms, metadata and encryption. Pure JavaScript.
pdf.js
Renders pages to a canvas so we can show thumbnails, turn pages into images, and read out the text layer. The same engine behind Firefox's PDF viewer.
Tesseract (WASM)
Recognises text in scans for the OCR tool, running in a background worker with its English language data bundled with the site.
Web Crypto
Generates the random keys, salts and initialisation vectors used when you password-protect a PDF with AES-256.
A tiny ZIP writer
When a tool produces several files, they are bundled into a ZIP locally — with about a hundred lines of code and no dependency.
Noto Sans (pre-subset)
The built-in PDF fonts only cover Latin text. When your text contains ₹, Devanagari, arrows or maths symbols, a pre-subset Noto Sans is embedded instead and shaped correctly — Devanagari conjuncts included. It loads only when it is actually needed.

How to verify the privacy claim

Open your browser's developer tools, go to the Network tab, and use any tool. You will see the page's own assets load, and nothing else — no request carrying your document leaves the device. The libraries are served from this site's own origin, not from a third-party CDN, so there is no external service in the path at all.

Writing in Hindi, or with the ₹ sign

The fonts built into PDF only cover Latin characters, so the text tools normally use those and keep your file small. If what you type contains the rupee sign ₹, Devanagari, Latin Extended, arrows or maths symbols, the tool switches to an embedded Noto Sans instead, and shapes the text properly — a Devanagari conjunct such as क्ष comes out as one joined glyph rather than three separate ones. Both decisions are made per run of text, so an English heading and a Hindi paragraph can live in the same document. This adds roughly 50–90 KB to the file, and only when such text is used.

Chinese, Japanese, Korean and emoji are not bundled — those fonts are many megabytes each. If a character cannot be drawn, the tool names it rather than quietly leaving a blank.

What a browser cannot do (yet)

High-fidelity conversion between Office formats (Word, Excel, PowerPoint) and PDF needs a desktop-class layout engine such as LibreOffice, which does not run in a browser tab. AI summarising and translation need a model server. Those are deliberately not offered here rather than offered badly. Everything else — the day-to-day PDF and image work, including OCR and non-Latin text — runs client-side.

Questions

Is my file uploaded anywhere?
No. The tools are static HTML, CSS and JavaScript. Your file is read into the tab's memory, processed there, and downloaded from there. There is no upload endpoint in the code.
Why does a big PDF sometimes feel slow?
Because your device is doing the work. Very large files or high-resolution page rendering can be heavy on a low-powered phone. Splitting the document first usually helps.
Are the libraries loaded from a CDN?
No. pdf-lib, pdf.js, Tesseract, fontkit and the Noto Sans fonts are all stored in this site's own vendor/ folder and served from the same origin. There is no third-party request anywhere in the app, which is what makes the privacy claim checkable: open the Network tab and every request goes to this domain.
